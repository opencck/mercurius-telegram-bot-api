# BRIEF — mercurius-telegram-bot-api

Локальный сервер Telegram Bot API для бота Меркурия. Образ собирается из официальных исходников `tdlib/telegram-bot-api`
на закреплённом коммите, без сторонних образов. В режиме `--local` бот скачивает и отправляет файлы до 2000 МБ, тогда
как облачный Bot API отдаёт боту файлы до 20 МБ. Модуль необязателен: по умолчанию бот работает с облаком.

## Назначение и границы

Модуль делает:

- собирает и запускает `telegram-bot-api` в режиме `--local` на порту 8081;
- держит файлы в `/var/lib/telegram-bot-api` — приложение читает их с того же тома по пути, который сообщает сервер;
- передаёт HTTP-прокси из `TELEGRAM_PROXY` для исходящих запросов webhook;
- следит, что сервер отвечает, и останавливает зависший контейнер.

Остаётся в приложении (`src/Infrastructure/Config/TelegramSettings.php`, `bootstrap/04-channel.php`, пакет
`packages/messenger`):

- выбор между облаком и локальным сервером (`TELEGRAM_API_URL`);
- однократный выход бота из облака (`logOut`) и отметка `storage/app/telegram-cloud-logged-out`;
- свой предел файла `TELEGRAM_FILE_LIMIT_MB` и чтение файла только внутри смонтированного каталога;
- путь к Telegram через прокси или VLESS для самого приложения (`TELEGRAM_PROXY`).

## Устройство

Своего кода, кроме сборки и скрипта запуска, нет; API — сам Bot API.

| Путь / файл | Что делает |
|---|---|
| `Dockerfile` | стадия сборки: `git clone` исходников, `git checkout` закреплённого коммита, `cmake`; итоговый образ — `debian:bookworm-slim` с бинарником, `curl`, `libssl3`, `zlib1g` |
| `entrypoint.sh` | проверяет `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`, запускает сервер с `--local --dir=/var/lib/telegram-bot-api --temp-dir=/tmp/telegram-bot-api --http-port=8081`, добавляет `--proxy` для `http://` и `https://`, держит сторожа |
| `:8081` | HTTP Bot API (`/bot<token>/<метод>`), как у облака |
| `/var/lib/telegram-bot-api` | файлы ботов; в Меркурии — `storage/telegram-api` |

Аргументы сборки: `TELEGRAM_BOT_API_COMMIT` (по умолчанию `7232881b…`, Bot API 10.4) и `BUILD_JOBS` (по умолчанию 1).

## Безопасность и пределы

- Без `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` контейнер завершается с ошибкой. Значения — с my.telegram.org, в
  `.env`, в образ не попадают.
- Своего токена у сервера нет: вход — токен бота в пути запроса. Порт наружу не публикуется: сервис только в сети
  `internal`.
- Образ: пользователь `telegram` (uid 10030).
- Сторож: опрос `http://127.0.0.1:8081/` раз в `WATCHDOG_PERIOD` секунд (по умолчанию 60), ответ ждёт 10 с; любой HTTP-
  ответ — сервер жив. Три пропуска подряд — сервер убивается, контейнер завершается, Docker запускает его заново
  (`restart: unless-stopped`).
- По SIGTERM и SIGINT скрипт передаёт сигнал серверу и ждёт его завершения.
- Приложение монтирует `storage/telegram-api` только для чтения.
- Compose: `mem_limit` и `read_only` не заданы; журнал — до 3 файлов по 20 МБ.

## Решения

- Сборка из исходников на закреплённом коммите: без чужих образов и с известной версией Bot API.
- `BUILD_JOBS=1` по умолчанию: компилятор tdlib берёт несколько ГБ памяти на задачу, а хост общий.
- `--proxy` только для `http://` и `https://`: у сервера прокси действует лишь на исходящие webhook-запросы, своё
  соединение с Telegram он через прокси не ведёт; socks5 и VLESS не используются — сложный шлюз не ставим.
- Сторож в скрипте запуска: однажды сервер перестал отвечать и доставлять webhook, не завершившись.
- Файлы читаются с общего тома, а не скачиваются по сети: так их отдаёт режим `--local`.

## Проверки

- CI (`.github/workflows/ci.yml`): `sh -n entrypoint.sh` и `shellcheck entrypoint.sh`. Образ в CI не собирается:
  сборка tdlib долгая и требует много памяти. Изменения только в `*.md` CI не запускают.
- Тестов в репозитории нет; образ собирается командой `docker compose` основного репозитория с профилем `telegram-api`.

## Связь с Меркурием

- Профиль compose — `telegram-api`: добавить в `COMPOSE_PROFILES`.
- `.env`: `TELEGRAM_API_URL=http://telegram-api:8081` (пусто — облачный Bot API), `TELEGRAM_API_ID`,
  `TELEGRAM_API_HASH`, `TELEGRAM_FILE_LIMIT_MB` (по умолчанию 200), `TELEGRAM_PROXY`.
- Вернуть бота в облако Telegram даёт только через 10 минут после `logOut`.
